# IAM 0.1.0 Documentation and Release Design

## Goal

Prepare `IAM Spring Boot Starter` 0.1.0 for release review by making its
tested consumer contract discoverable, runnable from zero, and independently
verifiable. This release-preparation scope does not add IAM protocols or new
authorization capabilities.

## Audience and writing rules

The primary reader is a Java/Spring Boot developer using the starter for the
first time. Documentation is Simplified Chinese, while Java symbols, HTTP
paths, configuration properties, and permission codes retain exact English
source names. Every API, configuration item, status, and command must trace to
current source code or an automated test. Examples use anonymous data only.

## Documentation architecture

`iam-docs/` is an Astro + Starlight static documentation site. Its
`src/content/docs/` directory is the canonical source for user documentation;
Starlight supplies side navigation, on-page TOC, search, copy buttons, syntax
highlighting, dark mode, responsive navigation, and previous/next navigation.

Repository-level `docs/` remains canonical for `QUICK_START.md`,
`PUBLIC_API.md`, release notes, migration, security, architecture, design, and
validation records. User pages link to these files rather than duplicating
long content. The site includes Introduction, Getting Started, Concepts,
Authentication, Authorization, Profile and Session, Diagnostics and Errors,
Migration, Operations, Reference, and Resources.

Astro + Starlight is chosen because it supplies the required documentation
experience without a custom SPA. VitePress is not selected because it provides
no advantage here over Starlight's documentation defaults. A raw Vite/Vue site
is rejected because its extra navigation and search implementation would be
release scope churn.

## QuickStart

`iam-example` remains the only consumer module. It already owns the tested
Document HTTP surface and public API boundary. A new, default-disabled demo
seed runs only under the `dev` profile with `iam.example.seed-demo=true`.
`examples/quickstart/docker-compose.yml` and `.env.example` provide local
MySQL 8.4 and Redis 7 only; all credentials are local demonstration values.

The scenario uses `alice`, `project-101`, `document-1001`, and
`document-2001`. A reader can read document 1001 but cannot update it or read
document 2001. A replacement editor-profile token can update document 1001;
the original reader token remains denied. Revoking the editor session makes
only that editor token invalid. The tutorial documents actual starter APIs:
`IdentityAuthenticator`, `ResourceHierarchyProvider`,
`MvcResourceDescriptorResolver`, `@RequirePermission`, login, profile switch,
session revoke, and diagnostics.

## Public contract and references

`docs/PUBLIC_API.md` and the site reference page list stable consumer APIs and
SPIs from source: identity authentication, principals, authorization engine
types, resource hierarchy/policy, declarative MVC types, sessions, profile
switching, and diagnostics. Mappers, persistence implementations, `internal`
packages, and migration objects are explicitly non-stable consumer APIs.

Configuration documentation is generated manually from current
`IamProperties`: general, token, session, schema, audit, diagnostics, and
client types. HTTP documentation is derived from the current OpenAPI contract
and controllers, grouped by authentication, session, authorization, profile,
administration, and diagnostics. Error reference documents the tested default
`application/problem+json` codes without sensitive IAM details.

## Release engineering

Version remains `0.1.0-SNAPSHOT` until the final release gate and explicit
human approval. Maven metadata may use only repository-verifiable license,
developer, SCM, and project facts; missing facts are findings, never invented.
No tag, GitHub Release, or Maven publication is created in this scope.

`docs.yml` verifies the documentation site on pull requests and `main` pushes
with `npm ci`, `npm run check`, and `npm run build`. A separate
workflow-dispatch-only Pages workflow may build/deploy static output but does
not enable or change repository Pages settings.

## Release gate

The release report records candidate branch/SHA, Java 21, Spring Boot 4,
MySQL 8.4, Redis 7, actual command evidence, and P0--P3 findings. Remote CI is
recorded as `Pending` unless actually observed. `READY FOR REMOTE CI / RELEASE`
requires Maven tests, auto-configuration, consumer smoke, public API boundary,
MySQL/Redis integration, MVC authorization status tests, QuickStart validation,
documentation build/link checks, and zero P0/P1 findings. New product ideas
are recorded only in a 0.2.0 roadmap.
