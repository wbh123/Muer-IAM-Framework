# IAM 0.1.0 Documentation Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a runnable Chinese QuickStart, Astro/Starlight documentation site, release documentation, and verifiable 0.1.0 release candidate.

**Architecture:** Reuse `iam-example` as the sole consumer example. Keep repository release material in `docs/`; use `iam-docs/src/content/docs/` as canonical user-document source. Add a default-disabled dev seed and compose infrastructure, then verify the same HTTP paths through existing integration tests.

**Tech Stack:** Java 21, Spring Boot 4, Maven, MySQL 8.4, Redis 7, Docker Compose, Astro, Starlight, npm, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-04-iam-0.1.0-documentation-release-design.md`

## Global Constraints

- Work only on `release/0.1.0`; do not merge, tag, publish artifacts, or create a GitHub Release.
- Version stays `0.1.0-SNAPSHOT` until the final human-approved release gate.
- Do not add OAuth/OIDC/SSO/JWT/SAML/LDAP/multi-tenancy/ABAC language or a new admin UI.
- API, configuration, endpoint, status, and example claims must match current source and tests.
- Record new feature ideas only as 0.2.0 roadmap items.

## Task 2: Make the existing consumer runnable as QuickStart

**Files:** Create `examples/quickstart/docker-compose.yml`, `examples/quickstart/.env.example`; modify `iam-example` dev configuration/seed code, `iam-example` tests, and `docs/QUICK_START.md`.

- [ ] **Step 1: Write failing dev-seed tests**

- [ ] **Step 2: Implement only default-disabled seed and Compose**

Use current public/host APIs and existing fixture semantics. Add MySQL 8.4/Redis 7 compose services and local demonstration environment variables. Keep the seed guarded by both profile/property and never invoke it in production defaults.

- [ ] **Step 3: Write/update HTTP acceptance flow**

Extend `IamConsumerIntegrationTest` or a dedicated QuickStart test to prove reader 200/403/cross-project 403, replacement editor write 200, original token stays 403, revoked editor token 401, and reader session remains valid.

- [ ] **Step 4: Write runnable QuickStart**
